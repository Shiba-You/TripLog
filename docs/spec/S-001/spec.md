# S-001 マップ（ホーム）受け入れ基準

## 概要

アプリ起動直後に表示されるメイン地図画面。ユーザーが記録した全旅行の経路（ポリライン）と訪問済みエリア（塗りつぶし）を一望でき、写真ピン・現在地・トロフィー進捗を重ねて確認できる。ここから旅行の絞り込み、トラッキング開始（S-002）、旅行一覧/家計簿/設定への遷移が行える。

## スコープ

### 対象

- S-001（マップ/ホーム）の5状態: 通常 / 位置許可未取得 / データ空 / ローディング / エラー
- 画面項目13点すべて（フィルタチップ、経路ポリライン、訪問エリア塗りつぶし、写真ピン、現在地ピン、トロフィー進捗バッジ、位置許可未取得バナー、データ空CTA、ローディングインジケータ、レイヤー表示切替、FAB、下部タブバー、エラー表示バナー）
- 処理11点すべて（画面表示時のAPI呼び出し、フィルタ操作、写真ピンタップ、FABタップ、タブタップ、位置許可バナー操作、エラー再試行操作）
- 上記に伴う欠損値・空値（NULL）表示仕様
- フィルタチップ・レイヤー表示切替の初期ON/OFF既定値
- 写真ピンのクラスタ表示方針（MapLibre標準クラスタリング機能を使用すること、タップ時のズームイン展開）
- トロフィー進捗バッジの対象region粒度（市区町村＝city固定）
- 地図の初期表示範囲決定ロジック（フォールバック優先順位）
- APIエラー時のエラー状態表示・再試行
- 位置情報許可ダイアログの自動表示、および許可ありとみなす判定基準

### 対象外

- S-002（トラッキング）、S-003（旅行一覧・新規作成モーダル）、S-004、S-005（写真詳細/コメント）、S-006、S-008、S-009 それぞれの画面内部の詳細な受け入れ基準（本specでは「遷移すること」までを対象とし、遷移先の内部挙動は各画面のspecに委ねる）
- Web版（W-001等）
- 認証・マルチユーザー化、Android対応（要件定義書 対象外事項）
- GPXインポートそのものの取込処理（S-008）
- トラッキング中の位置情報バッファリング・オフライン再送ロジック（S-002/F-005の責務）
- 写真ピンクラスタリングの具体的な数値パラメータ（クラスタ半径・展開ズームレベルの閾値等）の選定（MapLibre標準機能を使う方針まではAC化するが、具体値のチューニングはplan-agentの設計判断）

## 受け入れ基準

### AC-1: 初期表示（通常状態）の主要フロー
- Given: 位置情報許可が許可済みであり、`trips` が1件以上存在する
- When: ユーザーがアプリを開き S-001 を表示する
- Then: `GET /api/trips`・`GET /api/coverage?regionType=city`・AC-36の優先順位で確定した初期表示範囲に基づく `GET /api/photos?bbox=...&hasLocation=true`・表示対象旅行ごとの `GET /api/trips/{tripId}/tracks` → `GET /api/tracks/{trackId}/points?simplify=...` が呼び出され、すべて成功した後にローディングインジケータが消え、フィルタチップ（全ON、AC-3）・経路ポリライン・訪問エリア塗りつぶし・写真ピン・現在地ピン・トロフィー進捗バッジを含む地図が表示される
- 根拠: S-001画面定義書 処理No.1〜4、状態「通常」

### AC-2: 旅行フィルタチップの生成
- Given: `trips` が1件以上存在する
- When: 画面表示時に `GET /api/trips` が成功する
- Then: 取得した各旅行についてフィルタチップが1つずつ生成され、チップのラベル文字は `trips.name`、背景色は `trips.color` になる。チップの並び順はAPIレスポンス順（`started_on` 降順、NULLは最後、次いで `created_at` 降順）に従う
- 根拠: S-001画面定義書 画面項目No.1、処理No.1

### AC-3: フィルタチップおよびレイヤー表示切替の初期ON状態
- Given: 画面が初めて表示される（または再表示される）
- When: `GET /api/trips` が成功しフィルタチップが生成される
- Then: すべての旅行フィルタチップは初期状態でON（表示扱い）であり、かつレイヤー表示切替（写真ピン／経路／訪問エリア）の3トグルも初期状態ですべてONである。いずれもユーザーが明示的にOFFへ切り替えるまでON状態を維持する
- 根拠: S-001画面定義書 画面項目No.1・No.10、2026-08-11ユーザー回答Q1

### AC-4: 旅行フィルタチップ領域の非表示（データ空）
- Given: `trips` が0件である
- When: 画面表示時に `GET /api/trips` が成功し空配列が返る
- Then: フィルタチップ領域自体が表示されない
- 根拠: S-001画面定義書 画面項目No.1「欠損値・空値時の表示」

### AC-5: フィルタチップのタップによる表示切替
- Given: 通常状態でフィルタチップが表示されている（AC-3によりすべてON）
- When: ユーザーが特定の旅行のチップをタップしてON/OFFを切り替える
- Then: API再取得は行われず、クライアント側の再描画のみで該当旅行の経路ポリライン・関連写真ピンの表示/非表示が切り替わる
- 根拠: S-001画面定義書 処理No.5

### AC-6: 経路ポリラインの描画
- Given: フィルタチップがONの旅行に紐づく `tracks` が存在し、各 `track` に `track_points` が1件以上存在する
- When: 該当トラックの `GET /api/tracks/{trackId}/points?simplify=...` が成功する
- Then: 取得した経路が旅行の `color`（`trips.color`）で地図上にポリライン描画される
- 根拠: S-001画面定義書 画面項目No.2、処理No.4

### AC-7: 経路ポリラインの描画スキップ（トラックポイント無し）
- Given: フィルタチップがONの旅行に `track` は存在するが、当該 `track` に紐づく `track_points` が0件である
- When: 該当トラックの経路取得処理が行われる
- Then: そのトラックについてはポリライン描画をスキップし、エラー表示は行わない
- 根拠: S-001画面定義書 画面項目No.2「欠損値・空値時の表示」

### AC-8: 訪問エリア塗りつぶしの描画（市区町村単位）
- Given: `visited_regions` と `region_type='city'` の `regions` の結合結果が1件以上存在する
- When: `GET /api/coverage?regionType=city` が成功する
- Then: 返却された `geojson`（市区町村ポリゴンのみ）の各ポリゴンがアクセント色半透明のFillレイヤーとして地図上に塗りつぶし描画される
- 根拠: S-001画面定義書 画面項目No.3、処理No.2、2026-08-11ユーザー回答Q3（トロフィー進捗のregion粒度は市区町村のみを対象とし、`/api/coverage` のクエリパラメータもcity固定とする）

### AC-9: 訪問エリア塗りつぶし無し（参照データ未投入）
- Given: `region_type='city'` の `regions` 参照データが未投入である
- When: `GET /api/coverage?regionType=city` が成功するが `geojson` が空である
- Then: 塗りつぶしは描画されない（エラー表示は行わない）
- 根拠: S-001画面定義書 画面項目No.3「欠損値・空値時の表示」

### AC-10: 写真ピンの表示（サムネあり、非密集時）
- Given: 表示範囲内に `geom` が非NULL（`location_source <> 'unknown'`）かつ `thumbnail_key` が非NULLの写真が、地図上で他の写真ピンと密集していない状態で存在する
- When: 表示範囲確定後に `GET /api/photos?bbox=...&hasLocation=true` が成功する
- Then: 各写真についてサムネイル付きのピンが撮影地点に単体表示される
- 根拠: S-001画面定義書 画面項目No.4、処理No.3

### AC-11: 写真ピンのクラスタ表示
- Given: 表示範囲内・現在のズームレベルにおいて複数の写真ピンが密集している
- When: 写真ピンレイヤーが描画される
- Then: MapLibre標準のクラスタリング機能（デフォルトのradius/zoom設定）を用いて、密集したピンが1つのクラスタ表示（件数バッジ付き）にまとめられる。個別の数値パラメータ（半径・展開ズーム閾値等）はMapLibre標準デフォルト値をそのまま使用し、本ACでは特定の閾値を規定しない
- 根拠: S-001画面定義書 画面項目No.4「密集時はクラスタ表示にまとめる」、2026-08-11ユーザー回答Q2

### AC-12: クラスタピンタップによるズームイン展開
- Given: 写真ピンのクラスタが地図上に表示されている
- When: ユーザーがクラスタをタップする
- Then: 写真詳細画面へは遷移せず、そのクラスタが内包する範囲へ地図が自動的にズームインし、ズームの結果クラスタが分解されて個別ピン（またはより小さいクラスタ）が表示される
- 根拠: 2026-08-11ユーザー回答Q2（タップ時はクラスタ範囲へズームインして自動展開する）

### AC-13: 写真ピンのデフォルトアイコン表示（サムネ欠損）
- Given: 表示範囲内に `geom` が非NULLだが `thumbnail_key` がNULLの写真が存在する
- When: 写真ピン取得処理が行われる
- Then: 当該写真はデフォルトアイコンでピン表示される（クラスタに含まれる場合はクラスタ表示が優先される）
- 根拠: S-001画面定義書 画面項目No.4「欠損値・空値時の表示」

### AC-14: 写真ピン非表示（撮影地点不明）
- Given: `geom` がNULL（`location_source='unknown'`）の写真が存在する
- When: 写真ピン取得処理が行われる（`hasLocation=true` のため対象外として扱われる）
- Then: 当該写真はピンとして地図上に表示されない
- 根拠: S-001画面定義書 画面項目No.4「欠損値・空値時の表示」、API設計 `/api/photos` の `hasLocation` パラメータ

### AC-15: 写真ピンタップによる遷移（個別ピン）
- Given: 個別（クラスタでない単体）の写真ピンが地図上に表示されている
- When: ユーザーが写真ピンをタップする
- Then: 写真詳細（プレビュー＋コメント）画面へ遷移する。詳細画面自体の表示内容・API呼び出しの受け入れ基準はS-005側のspecで扱う
- 根拠: S-001画面定義書 処理No.6

### AC-16: 位置情報許可ダイアログの自動表示
- Given: OSの位置情報許可状態が「未確認（Not Determined）」である
- When: ユーザーがS-001を初めて（または許可状態が未確認のまま再度）表示する
- Then: 画面表示のタイミングでOSネイティブの位置情報許可ダイアログが自動的に表示される
- 根拠: 2026-08-11ユーザー回答Q6（画面表示時にOSの位置情報許可ダイアログを自動表示する）

### AC-17: 位置情報許可の判定基準
- Given: OSの位置情報許可ダイアログへの応答、または既存の許可状態が確定している
- When: 許可状態を判定する
- Then: 許可状態が「使用中のみ許可（When In Use）」または「常に許可（Always）」のいずれかであれば「許可あり」として扱う。許可状態が「未確認」「拒否」「制限」のいずれかであれば「許可なし」として扱う
- 根拠: 2026-08-11ユーザー回答Q6

### AC-18: 現在地ピンの表示（位置情報許可あり）
- Given: AC-17の判定基準で「許可あり」と判定されている
- When: 画面が表示される
- Then: 端末GPSから取得した現在地に現在地ピンが表示される
- 根拠: S-001画面定義書 画面項目No.5

### AC-19: 現在地ピン非表示と位置許可未取得バナーの表示
- Given: AC-17の判定基準で「許可なし」と判定されている
- When: 画面が表示される
- Then: 現在地ピンは表示されず、代わりに「位置情報を許可してください」の文言と「設定を開く」ボタンを含む警告バナーが表示される。このバナーはAPIデータ取得（ローディング・エラー状態）の成否とは独立して、権限状態のみに基づいて表示される
- 根拠: S-001画面定義書 画面項目No.5・No.7、状態「位置許可未取得」

### AC-20: 位置許可バナーの「設定を開く」操作
- Given: 位置許可未取得バナーが表示されている
- When: ユーザーが「設定を開く」ボタンをタップする
- Then: OSの設定アプリ（本アプリの設定画面）が開かれる
- 根拠: S-001画面定義書 処理No.10

### AC-21: トロフィー進捗バッジの表示（市区町村単位）
- Given: `GET /api/coverage?regionType=city` のレスポンスで `stats.totalCount`（市区町村の総数）が1以上である
- When: 画面表示時にレスポンスを受信する
- Then: 「`stats.visitedCount`/`stats.totalCount`」と「`stats.coverageRate`%」（いずれも市区町村単位の値）を表示するバッジが表示される
- 根拠: S-001画面定義書 画面項目No.6、処理No.2、2026-08-11ユーザー回答Q3

### AC-22: トロフィー進捗バッジの非表示（regions未投入）
- Given: `GET /api/coverage?regionType=city` のレスポンスで `stats.totalCount` が0である
- When: 画面表示時にレスポンスを受信する
- Then: トロフィー進捗バッジは表示されない
- 根拠: S-001画面定義書 画面項目No.6「欠損値・空値時の表示」

### AC-23: データ空CTAの表示
- Given: `trips` が0件である
- When: `GET /api/trips` が成功し空配列が返る
- Then: 「最初の旅行を作る」ボタンを含むカードが表示される（位置許可未取得バナーが同時に表示されうる条件下でも、両者は独立して表示される）
- 根拠: S-001画面定義書 画面項目No.8、状態「データ空」

### AC-24: データ空CTAのタップによる遷移
- Given: データ空CTAが表示されている
- When: ユーザーが「最初の旅行を作る」ボタンをタップする
- Then: S-003の新規作成モーダルへ遷移する。モーダル自体の入力項目・バリデーションはS-003側のspecで扱う
- 根拠: S-001画面定義書 画面項目No.8

### AC-25: ローディングインジケータの表示
- Given: 画面表示直後で、初回の `GET /api/trips`・`GET /api/coverage`・`GET /api/photos`・トラック関連APIのいずれかが未完了である
- When: 上記のいずれかのAPIレスポンスを待っている間
- Then: 画面中央にスピナーが表示され、経路・塗りつぶし・写真ピン・データ空CTA・エラー表示は表示されない（位置許可未取得バナーのみ権限状態に応じて独立に表示されうる）
- 根拠: S-001画面定義書 画面項目No.9、状態「ローディング」

### AC-26: ローディング終了後の状態遷移
- Given: ローディングインジケータが表示されている
- When: 上記すべての初回API呼び出しが完了する
- Then: いずれかのAPI呼び出しが通信エラー/サーバエラー（5xx）で失敗した場合は「エラー」状態（AC-27）へ、すべて成功し `trips` が0件なら「データ空」状態（AC-23）へ、1件以上なら「通常」状態（AC-1）へ遷移し、ローディングインジケータは非表示になる
- 根拠: S-001画面定義書 状態一覧、処理No.1〜4、2026-08-11ユーザー回答Q5

### AC-27: APIエラー時のエラー状態表示
- Given: 画面表示中、または再試行操作の結果として、`GET /api/trips`・`GET /api/coverage`・`GET /api/photos`・トラック関連APIのいずれかが通信エラーまたはサーバエラー（5xx）で失敗する
- When: 当該APIのエラーレスポンス（またはタイムアウト・通信不能）を受信する
- Then: ローディングインジケータは非表示になり、地図上に経路・塗りつぶし・写真ピン・データ空CTAは表示されず、「再試行」ボタン付きのエラー表示バナーが表示される。エラー表示バナーは他のいずれのAPIが失敗した場合であっても同一の表示形式で表示される
- 根拠: S-001画面定義書 状態「エラー」、画面項目No.13、2026-08-11ユーザー回答Q5

### AC-28: エラー状態からの再試行
- Given: エラー状態でエラー表示バナーが表示されている
- When: ユーザーが「再試行」ボタンをタップする
- Then: 直前に失敗したAPI呼び出しが再実行される。再試行の結果、成功すれば「データ空」（AC-23）または「通常」（AC-1）状態へ遷移し、再度失敗すれば引き続き「エラー」状態（AC-27）が表示される
- 根拠: S-001画面定義書 処理No.11、2026-08-11ユーザー回答Q5

### AC-29: レイヤー表示切替（写真ピン）
- Given: 通常状態で写真ピンが1件以上地図に表示されており、レイヤートグルは初期状態でON（AC-3）である
- When: ユーザーが「写真ピン」レイヤートグルをOFFにする
- Then: 地図上の写真ピンがすべて非表示になる（APIの再取得は発生しない）。再度ONにすると再表示される
- 根拠: S-001画面定義書 画面項目No.10

### AC-30: レイヤー表示切替（経路）
- Given: 通常状態で経路ポリラインが表示されており、レイヤートグルは初期状態でON（AC-3）である
- When: ユーザーが「経路」レイヤートグルをOFFにする
- Then: 地図上の経路ポリラインがすべて非表示になる（APIの再取得は発生しない）。再度ONにすると再表示される
- 根拠: S-001画面定義書 画面項目No.10

### AC-31: レイヤー表示切替（訪問エリア）
- Given: 通常状態で訪問エリア塗りつぶしが表示されており、レイヤートグルは初期状態でON（AC-3）である
- When: ユーザーが「訪問エリア」レイヤートグルをOFFにする
- Then: 地図上の訪問エリア塗りつぶしがすべて非表示になる（APIの再取得は発生しない）。再度ONにすると再表示される
- 根拠: S-001画面定義書 画面項目No.10

### AC-32: FABタップによる旅行選択ダイアログ表示
- Given: 通常状態またはデータ空状態で画面が表示されている
- When: ユーザーがFAB（トラッキング開始）をタップする
- Then: 旅行選択ダイアログが表示され、`GET /api/trips` の結果に基づく既存旅行の選択肢、および新規作成の選択肢が提示される

### AC-36: 地図初期表示範囲の決定（フォールバック優先順位）
- Given: 画面表示時点の状況が以下のいずれかに該当する
- When: 地図の初期中心座標・初期ズームレベルを決定する
- Then: 次の優先順位でフォールバックして初期表示範囲を決定する。
  1. 位置情報の許可あり（AC-17）かつ端末の現在地が取得できる場合、現在地を中心に表示する
  2. 上記が満たされない場合、直近（最新）のトラックポイントの座標を中心に表示する
  3. 上記も満たされない場合、全トラックポイントのbounding boxにフィットするよう表示する
  4. 記録されたトラックポイントが1件も存在しない場合、日本全体が収まる範囲を表示する
  写真ピン取得（`GET /api/photos?bbox=...`）は、この初期表示範囲が確定した後に、確定した範囲の `bbox` を用いて呼び出される
- 根拠: 2026-08-11ユーザー回答Q4

## 非機能要件（該当する場合のみ）

- 地図描画は取得したトラックポイントをそのまま全点描画するのではなく、`simplify` パラメータを用いてズームレベルに応じた間引き描画を行うこと（要件定義書5章「性能」、S-001処理No.4）。
- `GET /api/trips`・`GET /api/coverage`・`GET /api/photos` 等の一般的な取得系APIは、自宅サーバ・国内アクセス想定で300ms以内の応答を目標とする（要件定義書5章「性能」）。
- 現在地の生座標をログに出力しないこと（要件定義書5章「セキュリティ」、位置情報は機微データ）。
- 画面定義書の補足にある通り、現行API設計には全旅行横断の経路まとめ取得エンドポイントが無いため、フィルタON旅行数×トラック数分のAPI呼び出し（N+1）が発生する。これは既知の制約であり、本specのAC達成条件には含めないが、旅行数が多い場合の応答遅延は許容する（性能改善は将来検討事項）。
