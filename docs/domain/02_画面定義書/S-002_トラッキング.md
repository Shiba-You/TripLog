## 状態

記録中 / 一時停止 / 断絶警告 / 終了確認モーダル / 圏外（ローカル蓄積中）

## 処理

| No | トリガー | 処理内容 | 呼び出しAPI | クエリ（相当のSQL） |
|---|---|---|---|---|
| 1 | 記録開始（S-001のFABから遷移直後、または開始ボタン） | 新規トラック（ライブ記録セッション）を作成 | `POST /api/trips/{tripId}/tracks` | `INSERT INTO tracks (id, trip_id, user_id, source, status, started_at) VALUES (gen_random_uuid(), $1, $2, 'live', 'recording', now()) RETURNING id, started_at, status;` |
| 2 | 端末が位置情報を定期取得（数秒〜数十秒間隔）しバッファが一定量たまるたび | バッファ点をバッチ送信し、`last_point_at` 更新と訪問区画の増分判定を行う | `POST /api/tracks/{trackId}/points` | `INSERT INTO track_points (track_id, user_id, geom, elevation_m, speed_mps, accuracy_m, recorded_at) SELECT $1, $2, ST_MakePoint(p.lng, p.lat)::geography, p.elevation_m, p.speed_mps, p.accuracy_m, p.recorded_at FROM unnest($3::point_input[]) AS p;`<br>`UPDATE tracks SET last_point_at = (SELECT max(recorded_at) FROM track_points WHERE track_id = $1) WHERE id = $1;`<br>`INSERT INTO visited_regions (id, user_id, region_id, first_visited_at, first_trip_id) SELECT gen_random_uuid(), $2, r.id, now(), $4 FROM regions r WHERE ST_Contains(r.geom, ST_SetSRID(ST_MakePoint($5,$6),4326)) ON CONFLICT (user_id, region_id) DO NOTHING;` |
| 3 | 一時停止ボタンのタップ | トラック状態を `paused` に更新 | `PATCH /api/tracks/{trackId}` `{status: paused}` | `UPDATE tracks SET status = 'paused' WHERE id = $1 RETURNING status;` |
| 4 | 再開ボタンのタップ | トラック状態を `recording` に更新 | `PATCH /api/tracks/{trackId}` `{status: recording}` | `UPDATE tracks SET status = 'recording' WHERE id = $1 RETURNING status;` |
| 5 | 終了ボタン→終了確認モーダルで「終了する」 | トラック状態を `finished` に更新し終了時刻を記録。S-004（該当旅行詳細）へ遷移 | `PATCH /api/tracks/{trackId}` `{status: finished, endedAt}` | `UPDATE tracks SET status = 'finished', ended_at = now() WHERE id = $1 RETURNING trip_id, status, ended_at;` |
| 6 | クライアント側で`last_point_at`からの経過時間が閾値超過を検知 | 断絶警告バナーを表示（画面ローカルの判定。サーバ側の通知は別途、定期ジョブが監視しAPNsで送信） | - | - |
| 7 | ネットワーク不通を検出 | 取得済み点を端末ローカル（SQLite等）へ一時保存し、圏外表示に切替 | - | - |
| 8 | ネットワーク復帰 | ローカル蓄積分をまとめて再送 | `POST /api/tracks/{trackId}/points` | 上記No.2と同一クエリ |

## 補足

- 経過時間は現仕様では単純な `now() - started_at` の差分。一時停止区間を除いた「正味記録時間」にするかは要件として未確定のため、実装時に確認が必要（`tracks`テーブルに一時停止区間の保存カラムは無い）。
- サーバ側の断絶検知〜通知は `docs/01_基本設計/06_API設計.md` の「トラッキングと断絶検知」シーケンス（定期ジョブ→APNs）を参照。本画面はクライアント側の即時表示のみを担う。
