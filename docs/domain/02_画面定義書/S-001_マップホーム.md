## 目的

アプリを開いた瞬間に「自分の足跡（経路）と埋まった土地（訪問エリア）」が一望できること。（`docs/01_基本設計/05_画面設計.md` S-001参照）

## 状態

通常 / 位置許可未取得（バナー表示） / データ空（CTA表示） / ローディング / エラー（再試行ボタン付きエラー表示）

## 処理

| No | トリガー | 処理内容 | 呼び出しAPI | クエリ（相当のSQL） |
|---|---|---|---|---|
| 1 | 画面表示 | 旅行一覧を取得しフィルタチップを生成 | `GET /api/trips` | `SELECT id, name, color FROM trips WHERE user_id = $1 ORDER BY started_on DESC NULLS LAST, created_at DESC;` |
| 2 | 画面表示 | 訪問済みエリア（塗りつぶし用GeoJSON）と統計を取得 | `GET /api/coverage` | `SELECT r.id, r.region_type, r.name, ST_AsGeoJSON(r.geom) AS geometry FROM visited_regions vr JOIN regions r ON r.id = vr.region_id WHERE vr.user_id = $1;`<br>`SELECT COUNT(*) AS visited_count FROM visited_regions WHERE user_id = $1;`<br>`SELECT COUNT(*) AS total_count FROM regions;` |
| 3 | 画面表示（表示範囲確定後） | 表示範囲内の写真ピンを取得 | `GET /api/photos?bbox=...&hasLocation=true` | `SELECT id, trip_id, ST_X(geom::geometry) AS lng, ST_Y(geom::geometry) AS lat, thumbnail_key FROM photos WHERE user_id = $1 AND location_source <> 'unknown' AND geom && ST_MakeEnvelope($2,$3,$4,$5,4326)::geography;` |
| 4 | 画面表示（フィルタチップONの旅行ごと） | 各旅行のトラック一覧→各トラックの経路点を取得し地図に描画 | `GET /api/trips/{tripId}/tracks` → `GET /api/tracks/{trackId}/points?simplify=...` | `SELECT id FROM tracks WHERE trip_id = $1;`<br>`SELECT geom, recorded_at FROM track_points WHERE track_id = $1 ORDER BY recorded_at ASC;` |
| 5 | フィルタチップのタップ | 表示対象旅行の絞り込み（クライアント側の再描画。API再取得は行わない） | - | - |
| 6 | 写真ピンのタップ | 写真詳細（プレビュー＋コメント）へ遷移 | `GET /api/photos/{photoId}/comments`（詳細側の処理） | S-005参照 |
| 7 | FABのタップ（対象旅行未選択） | 旅行選択ダイアログ表示。既存旅行選択 or 新規作成 | `GET /api/trips`（選択肢） | 上記No.1と同一 |
| 8 | FABのタップ→旅行決定 | トラック（記録セッション）を作成しS-002へ遷移 | `POST /api/trips/{tripId}/tracks` | `INSERT INTO tracks (id, trip_id, user_id, source, status, started_at) VALUES (gen_random_uuid(), $1, $2, 'live', 'recording', now()) RETURNING id, status, started_at;` |
| 9 | タブバーのタップ | S-003（旅行一覧）／S-006（家計簿）／S-009（設定）へ遷移 | - | - |
| 10 | 位置許可バナーの「設定を開く」タップ | OS設定アプリを開く | - | - |
| 11 | エラー表示の「再試行」タップ | 直前に失敗したAPI呼び出しを再実行する | 失敗したAPI（`GET /api/trips` 等、上記No.1〜4のいずれか）を再実行 | 上記No.1〜4のいずれかと同一 |

## 補足

- 現行API設計（`06_API設計.md`）には「全旅行横断の経路まとめ取得」専用エンドポイントが無いため、旅行数×トラック数分のAPI呼び出しが発生する（N+1）。旅行数が増えた場合はパフォーマンス上の課題になり得るため、将来的に集約エンドポイント追加を検討する余地がある。
